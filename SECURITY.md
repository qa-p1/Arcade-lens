# Security policy

## Reporting

Report a vulnerability privately through GitHub's "Report a vulnerability" (Security tab of this repository), not in
a public issue. Expect an answer within a week. Fixes ship as a patch release through the normal rc → promote path. A
release found to be unsafe after it shipped gets the catalog's `bad` flag: Arcade Tools stops offering it and tells
installed copies to roll back.

## What Arcade Lens guards, and how

Lens looks at your screen, so the first thing to know is when anything leaves the computer: only when you choose an
action that does, and the action says so (a ↗ mark, and a preview of exactly what is sent). Lens has no telemetry, no
update check and no crash reporter.

| Surface | Protection | Tested by |
|---|---|---|
| Screen capture | The screen is read only when you start a selection (the shortcut, the tray, `arcade-lens --capture`, or a connected app asking through Link). X11: the pixels are read from the X server in the Lens process. Wayland: Lens asks the desktop's screenshot portal, which may ask you, and deletes the file the portal saved in Pictures as soon as it has read it. Windows and macOS: the system capture. The frozen frame stays in memory; nothing is written unless you choose Save, Pin or Annotate (a pin or editor on Wayland gets the image through a PNG in `arcade-lens/` under the temporary folder, which Lens sets to `0700` on a best-effort basis and deletes once the window has loaded it). A pin's Live checkbox re-captures its source area about five times a second while it is on. The only global key Lens registers is the activation shortcut. | Not covered by a test (needs a display). |
| Text recognition | On Linux, Lens runs the `tesseract` program found on `PATH`, in the standard install folders or in the folder the Arcade apps download into. The selection goes in on its standard input as a PNG and the result comes back on standard output: no shell, fixed arguments, no temporary file. The language list is cut down to codes that Tesseract reports as installed. A cancelled run is killed. Windows and macOS use the system's own recognition. Lens bundles no recognition model. | Not covered by a test (needs Tesseract). |
| Getting Tesseract | Only when you press Download in Settings › Text recognition. Arcade Link fetches it with `curl --proto =https --tlsv1.2` from a fixed GitHub release address and refuses it unless its SHA-256 matches the hash built into Link. On Linux it is unpacked into the shared Arcade folder; on Windows the installer is opened for you to finish; on macOS Lens asks Homebrew to install it. | Link's own tests (`engines::checksum_mismatch_is_rejected`) |
| What leaves the computer | Open, Search Web, WHOIS, Lookup, Maps and similar actions hand an address to your browser (`xdg-open`, `open`, `rundll32 url.dll,FileProtocolHandler`, or the browser you chose in Settings) when you choose them. The query is percent-encoded into the template of the service in Settings › Providers (DuckDuckGo, OpenStreetMap and who.is by default); Search Web sends at most 300 characters. Lens makes no request of its own for these. Lookup of an IP address is offered for public addresses only. Reverse image search is off until you configure a service; it then puts the picture on your clipboard and opens the service's page, and uploads nothing. | `crates/lens-core/src/settings.rs` (`templates_are_encoded`, `defaults_keep_history_plugins_and_image_search_off`), `crates/lens-actions/tests/pipeline.rs` (`reverse_image_search_is_off_until_configured_and_never_uploads`) |
| Secret guard | With `[privacy] guard_secrets` (on by default), an action that would send the selection anywhere (a search, a lookup, Send to my devices, a connected app's outbound action) is not offered when the selection contains something that looks like a secret (an API key, token or password, found by patterns), and is refused if invoked anyway. Copying the secret itself asks first; the redacted copy does not. Pictures of a selection with a secret ask before they are sent. The patterns are heuristics: a secret they do not recognize is not guarded. A chain with a step that sends something out follows the same rule (see Chains). The guard filters actions; it does not filter what an enabled plugin is handed. | `crates/lens-actions/tests/pipeline.rs` (`secrets_suppress_outbound_actions`, `a_confirmed_outbound_chain_is_refused_when_the_selection_holds_a_secret`, `copying_a_secret_asks_first_and_the_redacted_copy_does_not`), `crates/lens-actions/tests/arcade.rs` (`sends_have_real_effects_and_secret_findings_remove_even_image_sends`), `crates/lens-recognizers/src/text/secret.rs` (`known_formats`, `redaction`), `crates/lens-core/src/value.rs` (`secrets_do_not_leak_through_debug`) |
| Download action | Offered only for `http` and `https` addresses, and only when you choose it. Lens fetches the address with its own HTTP client (rustls on Linux, the system's TLS on Windows and macOS), reads at most 512 MiB and saves it in your Downloads folder under a name taken from the address with path separators and `\ : * ? " < > \|` replaced; an existing file is never overwritten. | `crates/lens-actions/tests/pipeline.rs` (`download_is_offered_only_for_http_and_https_addresses`), `crates/arcade-lens/src/host.rs` (`never_overwrites`, `saved_names_stay_in_the_folder`). The download itself is not covered by a test (needs a server). |
| Programs Lens starts | Every program is started directly with an argument list, never through a shell, and is found on `PATH`: the opener for addresses and files (above), your browser, editor and terminal from Settings, `wl-copy` or `xclip` (Linux copies from a one-shot command), `lp` (print), `dbus-send` (reveal in the file manager), `gdbus` (preview), `kdeconnect-cli`, `notify-send` (a notification, with the text as one argument), `ffmpeg`, `hyprctl` (Hyprland only), `tesseract`, and on Windows and macOS `powershell`, `reg`, `explorer`, `osascript`, `open` and `qlmanage`. The arguments are an address Lens recognized (`http`, `https`, `ftp`, `ws`, `wss`, `mailto`, `tel`), a provider template filled with the percent-encoded query, or an absolute or `~` path that exists; a relative path is never opened, so an argument cannot be taken for an option. On Hyprland the shortcut is a runtime key binding (`hyprctl`, dropped when the compositor reloads) whose command is the Lens path single-quoted for the compositor's `sh`. | `crates/arcade-lens/src/host.rs` (`quoting`, `a_missing_clipboard_helper_is_named`), `crates/lens-platform/src/hyprland.rs` (`quoting`, `shortcuts_translate_to_hyprland_keys`), `crates/lens-platform/src/autostart.rs` (`exec_quotes_paths`, `generated_login_entry_carries_ownership_and_quotes_the_executable`) |
| Commands and terminals | Text that looks like a command is never run on its own. Open Terminal + Paste opens your terminal with the command typed into an editable prompt (bash `read -e -i`); nothing runs until you press Enter (PowerShell cannot pre-fill its prompt, so on Windows Lens copies the command and opens PowerShell for you to paste). Run in Terminal always asks first, showing the exact text and every risk Lens detected (elevated privileges, package changes, downloads piped into an interpreter), then runs it in your terminal: `bash -c` on Linux and macOS, `powershell -Command` on Windows. Ping, Traceroute, DNS Lookup, TLS Info and SSH run or pre-fill a fixed command line whose only variable part is a domain name or an IP address that Lens parsed and checked first (letters, digits, dots, colons and hyphens), never the surrounding text. | `crates/lens-actions/tests/pipeline.rs` (`ocr_text_flows_into_structured_recognizers_and_actions_run`, `terminal_commands_for_hosts_carry_nothing_but_the_host`), `crates/lens-recognizers/src/text/command.rs` (`risks`) |
| Chains | A chain is a list of actions you saved (`chains.json`) and runs only when you pick it. A chain with a step that sends something out or runs a command asks for confirmation first, showing its steps, and refuses to run without it. With `[privacy] guard_secrets` on and a secret in the selection, a chain with a step that sends something out is not offered and is refused if run anyway; confirming does not override it, as for a single action. Chains whose steps stay on the computer are unaffected. | `crates/lens-actions/tests/pipeline.rs` (`chain_type_errors_are_caught`, `a_chain_with_a_dangerous_step_does_not_run_until_confirmed`, `a_confirmed_outbound_chain_is_refused_when_the_selection_holds_a_secret`) |
| Plugins | Off until you turn each one on in Settings › Plugins, which shows the permissions it declared. A plugin is a program in its own folder (`plugin.toml` plus an executable, or a `.py` file run with `python3`), started without a shell, in its own folder, speaking JSON over standard input and output, with a timeout per call (3 s to recognize, 30 s to act). Its permissions bound what Lens does for it: a plugin sees text or pixels only if it declared `read-text` or `read-pixels`, can only register actions whose effects it declared, and asks Lens to copy, open an address or save a file, each refused unless that action declared it. A plugin process is not sandboxed: it runs with your user's rights like any program you install, so enable only plugins you trust. Once enabled, a plugin that can read text is handed the text of every finding of the kinds it consumes, including a secret in it. | `crates/lens-plugins/tests/plugins.rs` (`isbn_plugin_recognizes_and_acts`: discovered but off by default, `undeclared_effects_are_refused`, `manifest_cannot_exceed_its_permissions`), `crates/lens-plugins/src/lib.rs` (`manifest_validation`) |
| Send to a device | Only when you choose Send to Phone, Send to Device or Send to my devices. If Arcade Clipboard is installed and linked, the content goes to it through Link. Otherwise Lens runs `kdeconnect-cli -d <device> --share <link or number>`, `--share-text <text>` or `--share <PNG file>` with the first reachable paired device KDE Connect lists; there is no device chooser. An image is written first to `arcade-lens-share-<process id>-<time>-<counter>.png` (mode `0600`) in Lens's private folder (see Files Lens writes), and Lens deletes shares older than one hour whenever it writes a new one (KDE Connect uploads the file after the command returns, so it cannot be deleted at once). | `crates/lens-actions/tests/arcade.rs` (`sends_have_real_effects_and_secret_findings_remove_even_image_sends`), `crates/arcade-lens/src/gui/ghost.rs` (`share_names_are_unique_per_share_and_per_process`, `a_share_is_written_private_and_two_shares_do_not_collide`, `writing_a_share_deletes_old_shares_only`). Running `kdeconnect-cli` itself is not covered by a test. |
| Clipboard | Lens writes the clipboard when an action copies, and reads it only for Compare with Clipboard on a hash, UUID or identifier, in memory, and shows only the verdict. It never watches the clipboard. | `crates/arcade-lens/src/host.rs` (`a_missing_clipboard_helper_is_named`). Reading is not covered by a test. |
| Link IPC | Arcade Link's sockets (0600, peer UID check, per-endpoint token). Lens offers five actions to other Arcade apps: select a region (you draw it in Lens's own overlay and only that region is returned), capture and act, analyze an image, recognize text in an image or text a caller hands over, and pin an image. Files travel through Link's private handoff folder. Entries other apps contribute to Lens's palette go through Lens's own effect classification (an effect Lens does not know counts as dangerous) and the secret guard, a peer that is switched off or missing is dropped from the palette, and a job has a 60-second limit. Settings › Connected apps switches each peer, or all of them, off. | Link's own tests, `crates/lens-actions/tests/arcade.rs` (`cached_pipelines_match_first_input_hide_interactive_and_enforce_effects`, `disabled_peers_and_live_unavailability_remove_cached_entries`), `crates/arcade-lens/src/link.rs` (`capture_job_cancel_releases_the_picker_before_the_gui_drains_its_queue`, `queued_images_survive_the_creators_handoff_cleanup`) |
| Control channel | The running Lens listens on `127.0.0.1` on a random port for its own command line (`--capture`, `--settings`, `--quit`). The port and a 256-bit random token are in a file only the user can read (`0600` on Linux and macOS; on Windows it sits in the user's own data folder), and a request without the token is answered "denied". A second instance refuses to start. | `crates/lens-platform/src/ipc.rs` (`roundtrip_and_token_check`, `the_endpoint_file_is_private`) |
| Windows | Lens draws its own windows with egui. It embeds no web view, HTML or script engine, so there is no page, content policy or remote content inside a Lens window. | Not covered by a test (a property of the dependency tree). |
| Files Lens writes | Settings (`settings.toml`) and chains in Lens's config folder; usage counters, opt-in history, saved colours and palettes (`collections/`) and a log (`logs/`, written only when Lens has no terminal) in its data folder; files you save go to your screenshots folder, Pictures/Arcade Lens or the folder you pick, and recordings to Videos/Arcade Lens. A save never overwrites a file and cannot leave its folder. Only the control-channel file, the KDE Connect shares and the private hand-over folder get explicit permissions (`0600`, `0600`, `0700`). That folder, used for the Wayland window hand-over and the shares, is `$XDG_RUNTIME_DIR/arcade-lens` when that is a folder you own, else `<temporary folder>/arcade-lens-<uid>` (on Windows, `arcade-lens` in your own temporary folder). Lens creates it with mode `0700` and, before every use, checks that it is a real folder (not a symlink), owned by you, with no group or other access; otherwise it refuses and writes nothing. Every other file takes the process's umask inside your own config and data folders. The usage counters record which kind of thing you chose which action for, never content. | `crates/arcade-lens/src/host.rs` (`never_overwrites`, `saved_names_stay_in_the_folder`), `crates/lens-core/src/usage.rs` (`serializes`), `crates/arcade-lens/src/gui/private_dir.rs` (`the_folder_is_created_private_and_per_user`, `the_runtime_folder_is_preferred_when_it_is_ours`, `a_folder_open_to_group_or_other_is_refused`, `a_symlink_in_place_of_the_folder_is_refused`) |
| History | Off by default (`[privacy] history_enabled`). When you turn it on, each selection leaves a thumbnail (at most 480 px, PNG) and a JSON summary (the kinds found, the first line of each, 60 characters at most, and a confidence) in `history/` in Lens's data folder, newest 200 kept. Secrets are masked in the summaries, also where they sit inside other text, and a selection that contains a secret is stored as a plain grey tile of the same size. Clear history in Settings removes every entry, and a save already queued when you clear writes nothing. | `crates/arcade-lens/src/gui/history.rs` (`saves_counts_and_clears`, `a_save_queued_before_clear_writes_nothing`, `a_thumbnail_never_shows_the_pixels_of_a_selection_with_a_secret`, `secrets_are_masked_inside_other_findings`), `crates/lens-core/src/settings.rs` (`defaults_keep_history_plugins_and_image_search_off`) |
| Recording | Record window is offered only where `ffmpeg` is on `PATH` and the session is X11 or Windows. Lens starts `ffmpeg` with a fixed argument list and the window's rectangle, writes an MP4 that never replaces another file, and stops `ffmpeg` when you stop the recording or when Lens exits. | `crates/arcade-lens/src/gui/pins.rs` (`a_dropped_recording_leaves_no_recorder`) |
| Settings handoff | Arcade Tools can export and restore Lens's settings through Link. The document carries an allow-list only (appearance, shortcut, image format, OCR languages, action preferences, date order, home currency and the privacy switches), at most 1 MiB, validated on import; service address templates, program paths, plugin state, chains, folders, history and usage never enter it. | Not covered by a test. |
| Crash reports and logs | Lens has no crash reporter and sends nothing. Its log (`logs/arcade-lens.log` in the data folder, local, rotated) holds Lens's own messages; `LENS_DEBUG=1` adds identifiers and timings, not what was selected. | Not covered by a test. |
| Installing itself | `arcade-lens --install` and `--repair` copy the running AppImage or app bundle into the user's folders and write the receipt, launcher and login entry through Arcade Link, entirely under the user's home; nothing is downloaded. `--uninstall` removes only what the receipt lists. | `crates/arcade-lens/src/app/installer.rs` (`appimage_install_uninstall_and_repair_use_explicit_temp_environment`) |
| Updates | Lens is installed and updated by Arcade Tools, which trusts a release only through its signed `manifest.json` (see Arcade Tools' SECURITY.md). | Arcade Tools' tests |

## Dependencies

`cargo deny check` (advisories, licences, bans, sources) runs in CI on every pull request. Advisories with a fix inside
the version range Lens already depends on are fixed by updating (rustls, rustls-webpki, webpki-roots, tokio, rustix and
others). Seven are accepted, each with its reason in `deny.toml`: a soundness advisory in glib 0.18 (and its
`proc-macro-error` build macro), which only the GTK tray backend of `tray-icon` uses and no Lens build compiles (Lens
uses `tray-icon` on Windows and macOS only; Linux uses `ksni`); "unmaintained" notices (no known vulnerability) for
`paste` (a build-time macro of the image decoder that rxing enables), `ttf-parser` (egui's font reader, which only
reads the fonts compiled into Lens) and `zvariant`, `zbus_names` and `zvariant_derive` (merged into zbus 6, while
`ashpd` and `ksni` are on zbus 5).

Third-party licences are in `THIRD_PARTY_NOTICES.md`, generated by `scripts/third-party-notices.py` (CI fails when it
is out of date) and shipped inside the AppImage, the Windows installer and the macOS bundle. The Linux AppImage bundles
no native library of its own, only the AppImage runtime at the front of the file; CI unpacks every AppImage it builds
and fails if a library or another program appears (`scripts/test_third_party_notices.py` covers that check).
